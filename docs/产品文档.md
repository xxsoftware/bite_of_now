# 智能每日饮食推荐 App "咬一口春天"产品需求文档 (PRD) - Phase 2 稳定版

## 1. 产品概述
### 1.1 产品背景
一款面向注重健康饮食、追求生活品质的本地化手机应用。通过结合本地庞大的结构化食谱库与用户自定义的云端AI大模型接口，提供兼顾**精细化时令（旬）**、**菜系风味平衡**、营养健康与个人口味的每日饮食推荐。

### 1.2 核心价值
- **极致的时令与风味体验**：首创“按旬推荐”与“菜系轮换”机制，真正做到“不时不食”与“久吃不腻”。
- **绝对的隐私安全**：所有用户数据（饮食记录、身体数据、API密钥）仅存储于本地，不上传任何第三方服务器。
- **零成本与高自由度**：采用“本地App + 用户自带API Key”模式，开发者无服务器运维成本，用户可自由选择最适合自己的AI模型。

### 1.3 目标用户
- 追求“不时不食”传统养生理念的美食爱好者。
- 面临“今天吃什么”选择困难，且希望口味多样化的上班族。
- 注重数据隐私，偏好本地化工具的极客与科技用户。
- 需要图文/视频双模态教学的烹饪初学者。

## 2. 产品架构与技术栈
### 2.1 整体架构
- **客户端**：移动端 App（iOS / Android）。
- **数据存储**：本地嵌入式数据库（如 SQLite），存储包含时令、菜系标签的万级食谱库、用户记录及配置信息。
- **AI 服务**：通过 RESTful API 调用第三方大模型（如通义千问、GPT等），API Key 由用户在 App 内自行配置与加密存储。
- **资源包**：内置默认食谱 JSON 数据包（含基础时令与菜系标签），支持本地导入/导出。

### 2.2 核心逻辑流
> 本地计算当前“旬”与用户近期“菜系记录” -> 提取本地上下文（时令/忌口/历史记录） -> 组装 Prompt 发送给 AI -> AI 返回推荐菜名 -> 本地数据库匹配详情并展示。

## 3. 核心功能模块详解

### 3.1 首页：智能每日推荐
**功能描述**：App 的核心入口，展示 AI 生成的当日三餐及加餐建议。

- **三餐卡片**：
  - 展示早餐、午餐、晚餐及加餐的推荐菜品。
  - **双重推荐理由标签**：
    - **时令标签**：如“ 5月下旬·初夏尝鲜”、“ 10月中旬·蟹肥菊黄”。
    - **菜系标签**：如“️ 川菜·麻辣开胃”、“ 粤菜·清淡滋补”。
  - **营养概览**：顶部展示当日推荐总热量及三大营养素（碳水/蛋白质/脂肪）比例。
- **交互操作**：
  - **换一换**：点击刷新单道菜品。系统需记录“不喜欢”的反馈，短期内不再推荐。
  - **我吃了**：一键将推荐菜品打卡到“饮食记录”中。

### 3.2 菜谱详情页：双模态教学与烹饪辅助
**功能描述**：展示具体菜品的制作方法，支持图文与视频切换，并提供实用的烹饪辅助工具。

- **基础信息**：菜名、所属菜系、预计耗时、难度、卡路里估算。
- **时令赏味期**：明确标注该菜品的最佳食用时间（如：最佳赏味期：3月上旬 - 4月中旬），过季菜品在搜索时给予提示。
- **模式切换**：
  - **图文模式**：食材清单（含用量）、分步骤图文详解、烹饪小贴士。
  - **视频模式**：嵌入本地或流媒体视频，支持倍速播放、关键步骤打点。
- **烹饪模式（实用工具）**：
  - 进入该模式后，手机屏幕保持常亮，防止做饭时频繁解锁。
  - 界面字体自动放大，方便远距离查看。
  - 支持语音自动播报当前步骤，解放双手。
- **辅助功能**：
  - **加入购物清单**：将所需食材一键添加至本地购物清单。

### 3.3 探索与食谱库
**功能描述**：本地海量食谱的检索与管理。

- **多维搜索与筛选**：
  - **按时令筛选**：新增“时令日历”Tab，以时间轴形式展示 1-12 月的上、中、下旬。点击“5月下旬”，展示所有标记为该时令的本地食谱（如：蚕豆、苋菜、樱桃肉）。
  - **按菜系筛选**：支持按八大菜系（川、鲁、粤、苏等）及“家常菜”、“异国料理”进行快速筛选。
- **用户自定义上传**：
  - 提供结构化表单：输入菜名、食材、步骤、上传封面及视频。
  - **标签选择**：用户需手动选择该菜品的“所属菜系”以及“最佳食用月份与旬”。
  - 数据直接写入本地数据库。
- **默认数据包**：
  - App 首次安装时，自动解压内置的 `default_recipes.json`，预置 100+ 道经典家常菜，并打好基础的时令与菜系标签。

### 3.4 饮食记录（本地日记）
**功能描述**：记录用户每日饮食，为 AI 推荐提供历史上下文。

- **快速打卡**：支持从推荐页一键导入，或从食谱库手动添加。
- **菜系与口味记录**：系统自动记录每道菜的菜系（如川菜）和味型（如麻辣），作为后续“口味轮换”算法的依据。
- **状态记录**：记录用餐后的饱腹感（饿/适中/撑）及心情。

### 3.5 数据管理（导入/导出）
**功能描述**：实现数据的本地备份、迁移与冲突处理。

- **导出功能**：
  - 将本地食谱库（含自定义时令/菜系标签）和饮食记录打包为 `.json` 文件。
  - 文件名格式：`DietApp_Backup_YYYYMMDD.json`。
  - 调用系统分享面板，支持保存到本地存储或发送至微信/网盘。
- **导入功能**：
  - 支持读取外部 `.json` 文件并解析写入数据库。
  - **冲突处理**：遇到同名食谱时，弹窗询问用户选择“覆盖”、“跳过”或“保留两者”。

### 3.6 购物清单
**功能描述**：将用户想做或想买的食材汇总，方便线下采购。

- **清单管理**：支持添加、删除、标记“已购买”食材。
- **来源关联**：食材可手动输入，也可从菜谱详情页一键导入。
- **智能分类（可选）**：根据食材名称自动归类（如：蔬菜区、肉类区、调料区），提升超市采购效率。

### 3.7 设置与 AI 配置
**功能描述**：管理应用个性化设置及 AI 接口。

- **AI 模型配置**：
  - **API Key（必填）**：用户输入大模型平台的密钥（支持密文显示，使用系统级安全存储加密）。
  - **Base URL（可选）**：自定义 API 请求地址（兼容第三方转发或本地模型）。
  - **Model Name（可选）**：指定调用的模型名称。
  - **测试连接**：发送测试请求，验证 Key 的有效性。
- **偏好设置**：
  - 忌口食材设置（如：不吃香菜、海鲜过敏）。
  - 身体目标设置（减脂、增肌、维持）。
  - 口味偏好（清淡、重口味、辣度）。

## 4. 推荐算法与 AI 逻辑

### 4.1 精细化时令逻辑（精确到“旬”）
- **本地计算**：App 启动时自动获取当前日期，计算所属的“月份+旬”（例如：今天是5月26日，计算结果为“5月下旬”）。
- **数据库匹配**：食谱表中新增 `best_season` 字段（List类型），存储如 `["5月上旬", "5月中旬"]` 等标签。
- **强约束推荐**：在组装 Prompt 时，将当前“旬”作为高权重条件。例如：“当前是5月下旬，请优先推荐当季最新鲜的食材（如初夏的樱桃、枇杷、蚕豆等）。”

### 4.2 菜系平衡与去重逻辑
- **口味轮换算法**：读取用户最近 3-5 条饮食记录，提取其 `cuisine`（菜系）和 `flavor`（味型）。
- **差异化 Prompt**：若检测到用户近期连续摄入同一菜系（如连续两顿川菜），AI 提示词将加入约束：“用户近期摄入较多[川菜/重辣]，今天的推荐请避开同类菜系，优先推荐[粤菜/淮扬菜]等口味清淡、鲜美的菜品，实现口味多样化。”
- **频率控制**：查询本地数据库，获取用户过去 7 天内已食用的菜品列表，要求 AI 严格避开这些菜品。

## 5. 非功能性需求

### 5.1 性能要求
- **冷启动速度**：App 启动时间不超过 2 秒。
- **本地检索**：万级数据量下，按时令或菜系筛选的响应时间小于 200ms。
- **离线可用性**：除“AI 推荐”和“在线视频加载”外，其余功能（查看食谱、记录、搜索、时令日历、购物清单）必须支持完全离线运行。

### 5.2 数据安全
- **本地加密**：用户的 API Key 需使用系统级安全存储（如 iOS Keychain / Android Keystore）进行加密保存。
- **隐私声明**：在设置页明确告知用户，所有饮食数据仅保存在本机，不会上传至开发者服务器。

### 5.3 兼容性
- 适配主流屏幕尺寸，支持深色模式（Dark Mode）。
